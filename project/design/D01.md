# Decision 1 — CLI surface and shallow composition root

**Decision.** `cmd/llm-lint` contains a one-line `main` and a testable `run`:

```go
var version = "dev" // -ldflags "-X main.version=..."

func main() {
    cwd, _ := os.Getwd()
    os.Exit(run(os.Args[1:], os.Stdin, os.Stdout, os.Stderr, os.Getenv, cwd))
}

func run(args []string, in io.Reader, out, errOut io.Writer,
    getenv func(string) string, cwd string) int
```

Every exit path flows through `run`'s returned code using the taxonomy in
CONVENTIONS.md. `run` is the composition root: it parses flags, resolves
config (D02), loads rules (D03), builds the walker (D04), engine (D05), cache
(D06), suppression filter (D07), and reporter (D08), and wires them. Deeper
seams (filesystem, inference client, cache store, clock) are injected at those
packages' boundaries, not threaded through `run`'s signature; integration
tests exercise `run` directly with fakes bound via the engine seam
(`engine.Client`, D05).

Flags (stdlib `flag`, package name `llm-lint` in usage output):

- positional `[path...]` — files/directories to lint, default `.`
- `-c key=value` (repeatable) — the sole channel for every agentkit setting:
  model, provider, auth, auth_file, generation, reasoning, and retry keys
  (D02). There is deliberately no `--model` (or other per-key) flag; all model
  configuration flows through `-c`, matching agent-repl.
- `--rules <path>` (repeatable) — additional rule files/dirs (D03)
- `--format text|json` — output format, default `text` (D08)
- `--concurrency N` — max in-flight inference calls, default 8 (D05)
- `--no-cache` — skip cache reads, still write (D06)
- `--stats` — one-line run summary on stderr (D08)
- `--verbose` — per-pair progress trace streamed live to stderr (D05/D06/D08):
  one line for every (rule, file) pair evaluated, emitted the moment that pair is
  judged, showing a pass/fail circle, the file path, and the rule id. Off by
  default; independent of `--format` (findings still render to stdout in the
  chosen format)
- `--list-rules` — list known rules and exit; performs no inference
- `-V`, `--version` — print the version string and exit 0 (identical behavior;
  `-V` is a short alias carried for release tooling that probes `tool -V`)
- `--help` — usage plus the model catalog to stdout, exit 0

`--help` output mirrors agent-repl's: llm-lint's own flags block, then a
`providers:` block listing each provider (D02's `Providers()`/`ProviderInfo`)
with its `auth=key (ENVVAR)` line and, where the provider supports it, an
`auth=sub (auth_file=~/.llm-lint/<provider>-auth.json)` line, then per provider
its catalogued models (`agentkit/catalog.ListCurated`) each with a reasoning
clause marking the default with `*`, then a footer contrasting bare `model=`
(provider derived, must be catalogued) with explicit `provider=` (any model,
pass-through). The catalog is compiled in, so the listing needs no network.

When `--verbose` is set, `run` creates one `report.VerboseSink` (D08) over
`errOut` and injects it as the `engine.TraceSink` on the `cache.CachingClient`
(D06), which streams each judged pair's pass/fail line the moment its verdict is
known; when unset it injects nil and no tracing occurs. There is
no post-run render — the lines have already streamed by the time the run
returns, so `run` only appends any `--stats` line afterward. On an operational
failure (exit 3) the run aborts with its error on stderr; whatever pairs were
judged before the abort have already streamed their lines, so the trace shows
partial progress up to the failure followed by the error line.

Error surface: flag-parse failures and config/rule errors (D02's `ErrConfig`,
including an unrouteable custom model and a bad `auth`/`auth=sub` combination)
print one line to stderr and return 2; operational failures (the wrapped
`error` D05's `Engine.Run` returns, and D02's `ErrAuth` for a missing env key
or token file) print to stderr and return 3. Any `Config.Warnings` (e.g. a pass-through
model's no-pricing notice) print to stderr once before linting and do not
affect the exit code. `run` never panics on user input; panics are reserved
for broken internal invariants.

**Rejected.** Subcommands (`llm-lint cache clean`, `llm-lint rules`): the tool
has one job; flat flags match `go vet`-family ergonomics and every settled
behavior fits them. Cobra/urfave dependency: stdlib `flag` suffices at this
surface size.

**Verification.**

- R-FR4R-EO0B — `run` on a tree yielding no findings (fake engine returns
  none) writes nothing to stdout and returns 0.
- R-FSCN-SFR0 — `run` with a fake engine yielding one error-severity finding
  returns 1.
- R-FTKK-67HP — `run` with a fake engine yielding only warning-severity
  findings prints them but returns 0.
- R-FUSG-JZ8E — an unknown flag prints usage to stderr and returns 2.
- R-FW0C-XQZ3 — `--version` prints exactly the version variable (default
  `dev`) to stdout and returns 0.
- R-2J16-KM75 — `-V` prints exactly the same version variable to stdout and
  returns 0, identically to `--version`, and appears in the `--help` usage
  string.
- R-FX89-BIPS — `--list-rules` prints one line per known rule (id, severity,
  enabled/disabled under the effective config, description) and returns 0,
  and the fake engine records zero calls.
- R-FYG5-PAGH — when the engine reports an operational failure (fake client
  erroring after retries), `run` prints the failure to stderr and returns 3.
- R-J6TT-EEVY — `--help` prints, in addition to the flags, the `providers:`
  block naming every provider with its env key (e.g. `google` with
  `GEMINI_API_KEY`) and the `auth=sub` line for the sub-capable providers
  (openai, x-ai), and lists catalogued model ids (e.g. `gemini-3.7-flash`)
  under their providers with reasoning clauses; it exits 0 and records zero
  inference calls.
- R-H1KL-BCFY — `run` with `--verbose` (fake engine/cache over ≥2 rules ×
  ≥2 files, concurrency > 1) writes to `errOut` one line per (rule, file) pair,
  each a complete well-formed `<circle> <path> <rule-id>` line (so no two writes
  interleave) whose leading circle is 🟢 for a passing pair and 🔴 for a failing
  one, followed by the file path then the rule id, single-space-separated with
  no colon and no cache hit/miss token; the set of lines is order-independent
  (completion order, not sorted); `out` carries only the findings it would have
  without the flag; and the same run without `--verbose` writes none of those
  lines to `errOut`.
- R-H2SH-P46N — `run` with `--verbose --format json` writes the findings as
  the JSON array to `out` (unchanged by the flag) and the per-pair `<circle>
  <path> <rule-id>` progress lines to `errOut`; the two streams do not intermix.
