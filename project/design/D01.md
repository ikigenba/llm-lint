# Decision 1 — CLI surface and shallow composition root

**Decision.** `cmd/llm-lint` contains a one-line `main` and a testable `run`:

```go
var version = "dev" // -ldflags "-X main.version=..."

func main() {
    cwd, _ := os.Getwd()
    os.Exit(run(os.Args[1:], os.Stdin, os.Stdout, os.Stderr, os.Getenv, cwd))
}

func run(args []string, in io.Reader, out, errOut io.Writer,
    getenv func(string) string, cwd string) int
```

Every exit path flows through `run`'s returned code using the taxonomy in
CONVENTIONS.md. `run` is the composition root: it parses flags, resolves
config (D02), loads rules (D03), builds the walker (D04), engine (D05), cache
(D06), suppression filter (D07), and reporter (D08), and wires them. Deeper
seams (filesystem, inference client, cache store, clock) are injected at those
packages' boundaries, not threaded through `run`'s signature; integration
tests exercise `run` directly with fakes bound via the engine seam
(`engine.Client`, D05).

Flags (stdlib `flag`, package name `llm-lint` in usage output):

- positional `[path...]` — files/directories to lint, default `.`
- `-c key=value` (repeatable) — the sole channel for every agentkit setting:
  model, provider, auth, auth_file, generation, reasoning, and retry keys
  (D02). There is deliberately no `--model` (or other per-key) flag; all model
  configuration flows through `-c`, matching agent-repl.
- `--rules <path>` (repeatable) — additional rule files/dirs (D03)
- `--format text|json` — output format, default `text` (D08)
- `--concurrency N` — max in-flight inference calls, default 8 (D05)
- `--no-cache` — skip cache reads, still write (D06)
- `--stats` — one-line run summary on stderr (D08)
- `--verbose` — per-pair progress trace streamed live to stderr (D05/D06/D08):
  one line for every (rule, file) pair evaluated, emitted the moment that pair is
  judged, showing a pass/fail circle, the rule id, and the file path. Off by
  default; independent of `--format` (findings still render to stdout in the
  chosen format)
- `--list-rules` — list known rules and exit; performs no inference
- `-V`, `--version` — print the version string and exit 0 (identical behavior;
  `-V` is a short alias carried for release tooling that probes `tool -V`)
- `--help` — the full catalog to stdout, exit 0

`--help` output follows agent-repl's layout, in this fixed section order:

1. a `usage:` line — `usage: llm-lint [flags] [path ...]`;
2. a `flags:` block — one aligned row per flag, `<short>, <--long> <arg>`
   (short-flag slot left blank for long-only flags) followed by a very short
   one-line description, descriptions aligned to a common column;
3. a `defaults:` line — the compiled-in built-in default, the fixed string
   `provider=google   model=gemini-3.7-flash   auth=key`, rendered verbatim and
   **independent of any `.llm-lint.json` or `-c`** (a help screen describes the
   out-of-the-box default, not the resolved config; runtime resolution per D02
   is unaffected);
4. a `providers:` block — one aligned row per provider (D02's
   `Providers()`/`ProviderInfo`): `<provider>  auth=key  (ENVVAR)`, with an
   `auth=sub  (auth_file=~/.llm-lint/<provider>-auth.json)` continuation line,
   aligned under the first, for each sub-capable provider;
5. per-provider model sections — a bare `<provider>` header then one row per
   catalogued model (`agentkit/catalog.ListCurated`), the model id aligned with
   its reasoning clause rendered `<term>={<choices>}` where `<term>` is the
   offering's reasoning term (`effort`, `thinking_level`, `thinking_budget`,
   `thinking`), each choice is `|`-separated inside the braces, the **default
   choice is prefixed with `*`** (e.g. `effort={low|*medium|high}`), a numeric
   budget range renders `<min>–<max>` (en-dash), a provider-default budget
   renders `dynamic`, and a model with no reasoning knob renders `—`;
6. a footer contrasting bare `model=` (provider derived, must be catalogued)
   with explicit `provider=` (any model, pass-through).

The catalog is compiled in, so the listing needs no network and performs no
inference. The `usage:` line is the same one the bad-flag path prints (see the
error surface below); the `flags:`/`defaults:`/`providers:`/model/footer
sections are `--help`-only.

When `--verbose` is set, `run` creates one `report.VerboseSink` (D08) over
`errOut` and injects it as the `engine.TraceSink` on the `cache.CachingClient`
(D06), which streams each judged pair's pass/fail line the moment its verdict is
known; when unset it injects nil and no tracing occurs. There is
no post-run render — the lines have already streamed by the time the run
returns, so `run` only appends any `--stats` line afterward. On an operational
failure (exit 3) the run aborts with its error on stderr; whatever pairs were
judged before the abort have already streamed their lines, so the trace shows
partial progress up to the failure followed by the error line.

Error surface: a flag-parse failure prints the stdlib `flag` error line
followed by the single `usage: llm-lint [flags] [path ...]` line to stderr and
returns 2 — the flag set uses `flag.ContinueOnError` with `Usage` rendering
only that one `usage:` line (never the `flags:` block or the model catalog, which
belong to `--help`), and `run` must not render it a second time (a second render
is the doubled-usage defect); config/rule errors (D02's `ErrConfig`, including
an unrouteable custom model and a bad `auth`/`auth=sub` combination) print one
line to stderr and return 2;
operational failures (the wrapped
`error` D05's `Engine.Run` returns, and D02's `ErrAuth` for a missing env key
or token file) print to stderr and return 3. Any `Config.Warnings` (e.g. a pass-through
model's no-pricing notice) print to stderr once before linting and do not
affect the exit code. `run` never panics on user input; panics are reserved
for broken internal invariants.

**Rejected.** Subcommands (`llm-lint cache clean`, `llm-lint rules`): the tool
has one job; flat flags match `go vet`-family ergonomics and every settled
behavior fits them. Cobra/urfave dependency: stdlib `flag` suffices at this
surface size.
