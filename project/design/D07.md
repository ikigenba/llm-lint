# Decision 7 — Inline suppression

**Decision.** Package `internal/suppress`. Suppression is a mechanical
post-inference filter over findings; no inference is involved and cached
verdicts pass through it like fresh ones (the cache stores unsuppressed
verdicts; a suppression edit changes file content and thus the cache key
anyway).

```go
func Filter(findings []engine.Finding, read func(path string) ([]byte, error)) ([]engine.Finding, error)
```

The marker is the substring `llm-lint:ignore`, recognized anywhere in a line —
llm-lint knows no comment syntaxes, so the marker works inside any language's
comments. Grammar after the marker: an optional comma-separated rule-id list
(`llm-lint:ignore no-sleep-in-tests,other-rule`); a bare marker suppresses
all rules.

Targeting: a marker suppresses findings on its **own line**; when the marker
line contains nothing but the marker and surrounding non-alphanumeric
characters (a comment-only line: `// llm-lint:ignore foo`, `# llm-lint:ignore`),
it instead suppresses findings on the **next line**. A named list suppresses
only those rule ids; other rules' findings on the same line survive.

Error surface: an unreadable file during filtering returns a wrapped I/O
error (caller exits 3); a marker with an empty list item is ignored as text,
never an error — suppression comments must not be able to break the lint.

**Rejected.** Per-language comment parsing: enormous surface for zero gain —
the substring rule is what `nolint`-family greps effectively do. A
file-level or block-level suppression form: not in the settled scope; line
and next-line cover the build-loop override use-case, and a file is excluded
wholesale via config globs instead. Suppressing pre-cache: storing raw
verdicts keeps the cache independent of suppression edits.

**Verification.**

- R-H8SC-8KMV — a finding on a line whose text contains
  `llm-lint:ignore <its-rule-id>` is filtered out.
- R-HA08-MCDK — a bare `llm-lint:ignore` on the finding line filters
  findings of every rule on that line.
- R-HB85-0449 — a comment-only marker line filters findings on the next
  line, and not on itself or later lines.
- R-HCG1-DVUY — a marker naming a different rule id leaves the finding
  intact.
