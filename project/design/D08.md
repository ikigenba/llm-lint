# Decision 8 — Reporting, formats, and exit computation

**Decision.** Package `internal/report`.

```go
func Text(w io.Writer, cwd, root string, findings []engine.Finding) error
func JSON(w io.Writer, findings []engine.Finding) error
func StatsLine(w io.Writer, s Stats) // stderr, only with --stats
func Verbose(w io.Writer, cwd, root string, entries []engine.TraceEntry) // stderr, only with --verbose

type Stats struct {
    Rules, Files, Pairs, Calls, CacheHits int
    InputTokens, OutputTokens             int64
    CostUSD                               float64
}
```

Findings are sorted deterministically before rendering — by (file, line,
rule) — so concurrent completion order never changes output. Text format, one
finding per line on stdout, paths relative to the invoker's cwd:

    <path>:<line>: <explanation> (<rule-id>)

Warnings and errors render identically (severity's only role is exit-code
computation); a clean run writes nothing to stdout. `--format json` instead
emits a JSON array (empty array when clean) of objects with exactly the keys
`rule`, `severity`, `file`, `line`, `evidence`, `explanation` — `evidence`
being the exact source line text (D05 guarantees it), which is what lets a
downstream consumer construct a stable finding identity; llm-lint itself
computes none. Exit computation (used by D01): any error-severity finding →
1; findings but all warnings → 0.

`StatsLine` writes a single human line to stderr after the run:

    llm-lint: 2 rules, 41 files, 82 pairs, 7 calls, 75 cache hits, 118k in / 2k out tokens, $0.0113

`Verbose` writes the `--verbose` audit trace to stderr after the run,
independent of `--format` (findings still render to stdout in the chosen
format). Entries are sorted deterministically by (file, rule) — like findings,
concurrent completion order never shows — and each renders on one line with the
path relative to the invoker's cwd:

    <path>: <rule-id> <hit|miss> <pass|fail>
    <path>: <rule-id> skipped

`hit`/`miss` comes from `TraceEntry.Cached`, `pass`/`fail` from `Outcome`; a
`skipped` entry (oversize, never judged) renders without the hit/miss token,
since no cache lookup occurred. Lines carry no `llm-lint:` prefix — the trace
is many lines meant to be greppable and sortable by the reader.

Diagnostics (skip warnings, no-rules warning, operational errors) always go
to stderr; stdout carries findings only, so pipes stay clean.

**Rejected.** SARIF or checkstyle formats: no consumer in the settled scope;
the JSON format carries everything needed and more formats are cheap to add
later behind `--format`. A minted stable finding id in the JSON: the
adjudication problem belongs to the build loop (settled during grilling);
emitting exact `evidence` preserves the capability without owning it.
Severity prefixes in text output: `go vet`-family output carries none and
the rule id suffix already identifies the rule.

**Verification.**

- R-HDNX-RNLN — text output renders `<path>:<line>: <explanation>
  (<rule-id>)` with the path relative to the invoking cwd (verified from a
  subdirectory of Root).
- R-HEVU-5FCC — JSON output is a valid array of objects with exactly the
  keys rule, severity, file, line, evidence, explanation, and `evidence`
  equals the flagged line's exact text; a clean run emits `[]`.
- R-HG3Q-J731 — `--stats` writes the one-line summary (including call,
  cache-hit, token, and cost figures from the run) to stderr and nothing
  extra to stdout; without the flag the line is absent.
- R-HHBM-WYTQ — findings supplied out of order render sorted by (file, line,
  rule) in both formats.
- R-H7O3-875F — `Verbose` renders trace entries supplied out of order sorted
  by (file, rule), each line the path relative to cwd followed by, for a judged
  pair, `<rule-id> <hit|miss> <pass|fail>` (hit from `Cached=true`, fail from
  `Outcome="fail"`), and for a skipped pair `<rule-id> skipped` with no
  hit/miss token.
