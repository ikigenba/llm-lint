# Decision 6 — Verdict cache

**Decision.** Package `internal/cache`, wrapped around the engine's Client
seam (D05) as a caching decorator, so the engine and reporter never know
whether a verdict was inferred or replayed.

```go
type Store struct {
    Dir  string           // default os.UserCacheDir()/llm-lint
    Now  func() time.Time // injected for pruning tests
}

type CachingClient struct {
    Store   *Store
    Next    engine.Client
    NoRead  bool // --no-cache: skip reads, still write
    Hits    *atomic.Int64
    Trace   engine.TraceSink // nil unless --verbose (D01); streams each judged pair live
}

func Key(rulePromptAndMeta, fileContent []byte) string // sha256 hex
```

The key hashes the rule's full content (prompt + frontmatter — an edited glob
or severity is a different rule) and the file's content. The model is
deliberately not part of the key: a verdict is addressed by rule and file
content alone, so changing the model has zero effect on cache hits and never
triggers a re-judge. One entry per key: a JSON file `<key>.json` under a two-char fan-out
subdirectory, holding the findings array (empty array for a clean verdict —
clean is the common case and is cached identically). Entry reads bump mtime;
entries whose mtime is older than 30 days are opportunistically deleted
during normal runs (best effort, after the lint completes).

Cache misses call `Next` and write the entry on success; operational failures
are never cached.

When `Trace` is set, each judged pair calls `Trace.Add` with one
`engine.TraceEntry` the moment its verdict is known — streamed live, not
buffered: `Cached=true` for a read hit, `Cached=false` for a miss (a
`NoRead` run always misses, so its judged pairs all record `Cached=false`);
`Outcome="fail"` when the verdict carries ≥1 finding, `"pass"` when it is
clean. The verdict recorded is the **raw** one — the model's or the replayed
entry's — before D07 suppression runs, so a pair whose only finding is later
suppressed still traces as `fail`. A pair whose miss ends in an operational
failure aborts the run (D05) and records no entry. Corrupt or unreadable entries are treated as misses and
overwritten — the cache is disposable by construction, and deleting `Dir` is
the documented reset. All cache I/O errors degrade to miss-and-continue with
a stderr warning at most once per run; a broken cache never fails a lint.

**Rejected.** Caching in the repo (a committed lockfile): verdicts are
machine-local artifacts keyed by content, and committing them invites merge
noise and staleness; content-hash keys already share correctly across
worktrees. A cache-management subcommand: nothing to manage — pruning is
automatic and the reset is `rm -rf`. Including line numbers or file paths in
the key: content-addressing already invalidates exactly when content changes;
paths would break sharing across renames for no correctness gain. Including the
model id in the key: deliberately excluded — a re-judge should follow only a
file or rule change, and model changes must have zero effect; keying by model
would re-judge an unchanged tree whenever the model moved, the opposite of the
intended behavior.

**Verification.**

- R-H1GX-XY6P — an immediate identical re-run (same rules and files) makes
  zero calls on the fake Client and reports identical findings.
- R-H2OU-BPXE — editing one rule's file invalidates only that rule's pairs:
  the fake Client sees calls for the edited rule only.
- R-H3WQ-PHO3 — editing one linted file invalidates only that file's pairs.
- R-H54N-39ES — with `NoRead` set, a warm cache is not read (fake Client is
  called) but is written: a following normal run hits without calls.
- R-H6CJ-H15H — entries with mtime older than 30 days (injected clock) are
  removed by a normal run; younger entries survive.
- R-H58A-GNO1 — with a `Trace` set, a judged pair served from a warm cache
  adds a `TraceEntry` with `Cached=true`, while a pair that misses and calls
  `Next` adds one with `Cached=false`.
- R-H6G6-UFEQ — with a `Trace` set, a pair whose verdict carries ≥1 finding
  adds `Outcome="fail"` and a clean verdict adds `Outcome="pass"`, and the
  recorded outcome is the raw pre-suppression verdict: a pair whose sole
  finding is suppressed by D07 still traces as `fail`.
