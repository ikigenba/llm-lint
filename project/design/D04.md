# Decision 4 — Candidate file walking

**Decision.** Package `internal/walk`.

```go
type Walker struct {
    Root    string   // config root (D02)
    Exclude []string // global globs from config
    RunGit  func(dir string, args ...string) ([]byte, error) // injected
}

func (w *Walker) Files(paths []string) ([]string, error)
func Candidates(files []string, r rules.Rule) []string
```

`Files` expands the positional arguments (default `.`) into the lintable file
set, paths returned relative to `Root`, sorted:

- Inside a git work tree, enumeration is
  `git ls-files --cached --others --exclude-standard -z -- <paths>` — git's
  own matcher supplies exact `.gitignore` semantics (nested files, negations)
  at zero dependency cost. Outside one (or when `git` is unavailable), a
  plain `filepath.WalkDir` that skips `.git` directories is the fallback.
- An explicitly named file argument is always included, even if ignored —
  naming a file is opting it in (linter convention).
- Binary files are dropped by content sniff: a NUL byte in the first 8 KiB.
- Global `Exclude` globs (doublestar, matched against the Root-relative path)
  filter the set.

`Candidates` filters the walked set down to one rule's view: paths matching
any of the rule's `include` globs and none of its `exclude` globs. A file
matching no enabled rule is never read into a prompt.

Error surface: an unreadable named path or a failing git invocation returns a
wrapped error (caller exits 2 for a bad user-supplied path, 3 for I/O
failures mid-walk); an unreadable file discovered during the walk is skipped
with a stderr warning rather than failing the run.

**Rejected.** Reimplementing `.gitignore` matching, or depending on a
gitignore library: git itself is the only bug-free matcher, and it is already
present everywhere the tool runs; the non-repo fallback keeps the tool usable
on bare directories. Respecting ignore files in the fallback walk: without
git semantics any partial imitation misleads; the fallback is deliberately
plain.

**Verification.**

- R-GJ6G-7E2A — in a git-repo fixture with a `.gitignore`d file, `Files`
  omits the ignored file and includes tracked and untracked-unignored ones.
- R-GKEC-L5SZ — outside a git repo the fallback walk returns the tree's
  files and nothing under `.git/`.
- R-GLM8-YXJO — a file whose first 8 KiB contains a NUL byte is excluded.
- R-GO21-QH12 — a file matching a global `Exclude` glob is excluded.
- R-GP9Y-48RR — `Candidates` returns exactly the files matching the rule's
  include globs minus its exclude globs (doublestar `**` semantics
  demonstrated).
- R-GQHU-I0IG — with no positional arguments the walk covers `.`; an
  explicitly named file is included even when gitignored.
