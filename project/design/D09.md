# Decision 9 — Built-in rule: no-sleep-in-tests

**Decision.** The v1 built-in catalog is exactly one rule,
`internal/rules/builtin/no-sleep-in-tests.md`:

- `description`: fixed-duration sleeps in tests papering over timing or
  synchronization issues
- `severity`: `error`
- `include`: test-file globs across ecosystems —
  `**/*_test.go`, `**/*_test.py`, `**/test_*.py`, `**/*.test.js`,
  `**/*.test.ts`, `**/*.spec.js`, `**/*.spec.ts`
- `exclude`: none

The prompt body is language-agnostic: flag fixed-duration delays whose
purpose is to wait out a concurrent or asynchronous effect before asserting —
`time.Sleep`, `sleep()`, `asyncio.sleep`, `setTimeout`-as-wait, and
equivalents — and explicitly spare the legitimate uses: a sleep that is
itself the behavior under test (timeout logic, rate limiting, clock code),
polling loops with a deadline and a real condition check, and delays in
skipped/disabled code. The body includes one short flagged and one short
spared example to anchor the judgment. Exact prompt wording is the build
loop's to write and tune within this frame.

This rule is active by default like every rule in the catalog (D03): a project
with no config runs it, and silences it with `disable: ["no-sleep-in-tests"]`
if unwanted.

**Rejected.** A Go-only rule: the judge is a language model; hardcoding one
language wastes its advantage, and the globs already scope cost. Keeping it
off by default: the earlier nothing-on-by-default stance was a bootstrap
constraint from before the tool existed to dogfood; with llm-lint installed,
every rule is on by default (D03) and opt-out is per rule.
