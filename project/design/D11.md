# Decision 11 — Self-lint gate (dogfooding)

**Decision.** The llm-lint repository lints itself. The build loop's **verify**
turn runs the installed `llm-lint` binary over the working tree and requires it
to report no findings, as a completion gate alongside the green suite
(CONVENTIONS.md). Because `llm-lint` calls a language model, the gate runs
**only when a provider API key is present** in the environment and is **skipped
otherwise**, mirroring the live integration tests so credential-free suite green
is preserved.

The repo ships a root `.llm-lint.json`:

```json
{
  "enable": ["no-sleep-in-tests"],
  "exclude": ["testdata/**"]
}
```

`enable` deliberately pins the gate to `no-sleep-in-tests` alone (originally
explicit so the pre-default-on installed binary linted it; kept narrow now so
an untuned judgment rule — `boolean-state-machine`, D12 — cannot wedge the
verify turn with false positives; widening the gate is a later decision after
that rule's prompt is tuned against this tree). `exclude` is
the global path-glob list (D02 `Config.Exclude`, applied by the walker, D04)
that keeps the deliberately anti-pattern fixtures under `testdata/` out of every
run.

This decision introduces **no new Go package or seam**: the gate is a
loop-prompt check keyed off CONVENTIONS' green-bar, and the config is ordinary
data consumed by the existing config, walk, and rules machinery (D02–D04). The
binary is whatever is installed on `PATH` (the operator keeps the installed
version at or ahead of the built source).

**Rejected.**

- **llm-lint as part of the always-on green-bar.** Would force every green
  check — including offline `go test` and CI without credentials — to require a
  provider key and network, breaking the settled credential-free-green
  property. A keyed gate that skips without a key keeps both dogfooding and
  offline green.
- **Suppressing the `testdata/` fixtures with inline `llm-lint:ignore`
  comments** instead of a directory exclude. The fixtures exist precisely to be
  anti-patterns; one durable `testdata/**` exclude states that intent once,
  where per-line markers would have to be maintained on every fixture and could
  silently drift.
- **Leaving dogfooding to a separate manual or audit pass.** The verify turn is
  where a phase's completion is judged; running the lint there makes
  "lint-clean" a condition of done, not an afterthought a human must remember.

**Verification.** None — structural. This decision builds no Go behavior to
assert: its realization is the shipped `.llm-lint.json` (created by the plan
phase) plus the regenerated verify prompt that runs the gate. The config's
effect on rule selection and path filtering is already proven by the behavioral
ids of D02–D04.
