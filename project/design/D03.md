# Decision 3 — Rule model and catalog

**Decision.** Package `internal/rules`.

```go
type Rule struct {
    ID          string   // filename stem
    Description string
    Severity    Severity // SeverityError | SeverityWarning
    Include     []string // doublestar globs, relative to config Root
    Exclude     []string
    Prompt      string   // markdown body
    BuiltIn     bool
}

func Parse(name string, src []byte) (Rule, error)
func BuiltIns() []Rule                       // from an embed.FS of rule files
func Load(root string, paths []string) ([]Rule, error) // local rule files/dirs
func Select(all []Rule, enable []string) ([]Rule, error)
```

A rule file is markdown with a strict hand-parsed frontmatter subset (ralph
precedent, no YAML dependency): a leading `---` line, `key: value` lines, a
closing `---`, then the prompt body. Keys: `description` (string), `severity`
(`error`|`warning`), `include` and `exclude` (JSON string arrays, parsed with
`encoding/json`). `include` is required and must be non-empty; `exclude`
defaults empty. The rule id is the filename stem and must match
`[a-z0-9][a-z0-9-]*`.

Built-in rules are `.md` files under `internal/rules/builtin/` compiled in via
`go:embed`. `Load` accepts files and directories (a directory contributes its
`*.md` entries, non-recursive). `Select` returns exactly the rules whose ids
appear in `enable`, in `enable` order.

Error surface (all returned as `ErrRule` wrapping the file name and reason;
caller exits 2): unterminated or malformed frontmatter, unknown key, invalid
severity, empty/missing `include`, invalid id, unreadable path, a local rule
id colliding with a built-in or another local rule, an `enable` entry naming
no known rule. An empty `Select` result is not an error: the caller (D01)
prints `llm-lint: no rules enabled` to stderr and exits 0.

**Rejected.** YAML frontmatter via a library: two scalars and two arrays do
not justify the dependency. Rule id declared inside frontmatter: a second
identity to keep in sync with the filename; the stem is the single source.
Auto-discovering a conventional local rules directory: explicit config only
(the config must exist to enable anything, so implicitness saves nothing and
hides a rule source).

**Verification.**

- R-GAN5-IZVF — `Parse` on a well-formed rule file yields id = stem,
  description, severity, include/exclude, and the exact body as `Prompt`.
- R-GBV1-WRM4 — malformed frontmatter (unterminated fence, unknown key,
  severity other than error/warning, missing/empty include) returns `ErrRule`
  naming the file.
- R-GD2Y-AJCT — `Select` returns exactly the enabled rules: enabling one of
  two known rules yields only it.
- R-GEAU-OB3I — `Load` reads a directory entry (its `*.md` files) and an
  explicit file entry into rules.
- R-GFIR-22U7 — a local rule whose stem equals a built-in id (or another
  local id) returns `ErrRule` naming the collision.
- R-GGQN-FUKW — `Select` with an `enable` entry naming no known rule returns
  `ErrRule` naming the unknown id.
- R-GHYJ-TMBL — `run` (D01) with an empty effective enable list prints a
  `no rules enabled` warning to stderr and returns 0.
